Programación orientada a objetos y patrones de diseño

Cada tema sigue el mismo recorrido: explicación desde cero, su lugar en la programación, un esquema visual y un ejemplo en código.

Objeto

Introducción

Piensa en una receta y en el plato que sale de ella. La receta es el molde; el plato es algo real que puedes tocar y comer. Un objeto es esa cosa concreta: tiene características (color, tamaño) y sabe hacer cosas.

En programación

La clase es el molde y el objeto es una instancia creada con ella. Un objeto reúne estado (atributos), comportamiento (métodos) e identidad: dos perros llamados igual siguen siendo dos objetos distintos.

Ejemplo visual

Ejemplo en código

class Perro:
    def __init__(self, nombre, edad):
        self.nombre = nombre      # atributos
        self.edad = edad

    def ladrar(self):             # comportamiento
        return f"{self.nombre}: guau"

rex = Perro("Rex", 3)
luna = Perro("Luna", 5)
print(rex.ladrar())               # Rex: guau
print(rex is luna)                # False: identidades distintas

Abstracción

Introducción

Para conducir un carro usas volante y pedales; no necesitas saber cómo el motor inyecta combustible. Abstraer es quedarte con lo importante y esconder el resto.

En programación

Se modela solo lo que el problema necesita. Cómo abstraer:

  1. Identifica qué necesita el cliente del objeto (el qué, no el cómo).
  2. Define un contrato: clase abstracta o interfaz.
  3. Implementa los detalles en clases concretas.

El cliente depende del contrato, no de la implementación, y por eso puedes cambiar una sin tocar el resto.

Ejemplo visual

Ejemplo en código

from abc import ABC, abstractmethod

class Pago(ABC):                       # el contrato
    @abstractmethod
    def procesar(self, monto): ...

class PagoTarjeta(Pago):               # detalle oculto
    def procesar(self, monto): return f"Tarjeta: {monto}"

class PagoPSE(Pago):
    def procesar(self, monto): return f"PSE: {monto}"

def cobrar(pago: Pago, monto):         # solo conoce el contrato
    return pago.procesar(monto)

print(cobrar(PagoPSE(), 50000))

Herencia

Introducción

Heredas rasgos de tus padres sin que nadie te los enseñe, y además tienes los tuyos. Con las clases pasa igual: una nueva parte de otra ya hecha y le agrega lo suyo.

En programación

Una subclase reutiliza los atributos y métodos de su superclase y puede sobrescribirlos (override). Modela una relación "es un": un Perro es un Animal. Como acopla fuertemente las clases, si la relación no es un "es un" genuino conviene usar composición ("tiene un").

Ejemplo visual

Ejemplo en código

class Animal:
    def __init__(self, nombre):
        self.nombre = nombre
    def sonido(self):
        return "..."

class Perro(Animal):                   # Perro ES UN Animal
    def sonido(self):                  # override
        return "Guau"

class Gato(Animal):
    def sonido(self):
        return "Miau"

for a in (Animal("x"), Perro("Rex"), Gato("Misi")):
    print(a.nombre, a.sonido())        # polimorfismo

Patrones de diseño

Introducción

Un arquitecto no inventa desde cero cómo poner una escalera: usa soluciones que ya funcionaron muchas veces. Un patrón de diseño es una solución probada a un problema que se repite.

En programación

Son plantillas conceptuales, no código para copiar. El catálogo clásico es el de la "Banda de los Cuatro" (GoF, 1994): 23 patrones en tres grupos. Dan vocabulario común al equipo y código más mantenible; el riesgo es aplicarlos sin necesidad (sobreingeniería).

Ejemplo visual

Ejemplo en código

Singleton: garantiza una única instancia.

class Config:
    _instancia = None

    def __new__(cls):
        if cls._instancia is None:
            cls._instancia = super().__new__(cls)
        return cls._instancia

assert Config() is Config()            # siempre el mismo objeto

Modelo Vista Controlador (MVC)

Introducción

En un restaurante, la cocina prepara la comida, el mesero toma tu pedido y lo lleva, y tú ves el plato servido. Cada uno tiene su trabajo y nadie hace el de otro.

En programación

Es un patrón arquitectónico que separa la aplicación en tres partes. El Modelo guarda datos y reglas de negocio (la cocina). La Vista muestra información (el plato). El Controlador recibe las acciones del usuario, llama al modelo y elige la vista (el mesero). Ventaja: el modelo se prueba sin interfaz. Riesgo: controladores "gordos" con lógica que no les corresponde.

Ejemplo visual

Ejemplo en código

class Modelo:
    def __init__(self):
        self.tareas = []
    def agregar(self, texto):
        self.tareas.append(texto)

class Vista:
    def mostrar(self, tareas):
        print("\n".join(f"- {t}" for t in tareas))

class Controlador:
    def __init__(self, modelo, vista):
        self.modelo, self.vista = modelo, vista
    def crear(self, texto):            # acción del usuario
        self.modelo.agregar(texto)
        self.vista.mostrar(self.modelo.tareas)

Controlador(Modelo(), Vista()).crear("Estudiar MVC")

Abstract Factory

Introducción

En una mueblería compras sets: si eliges el estilo moderno, la silla, la mesa y la lámpara son modernas y combinan. La fábrica de cada estilo se encarga de que las piezas sean de la misma familia.

En programación

Patrón creacional que crea familias de objetos relacionados sin que el cliente conozca sus clases concretas. Para cambiar de familia (tema claro u oscuro, por ejemplo) basta con cambiar la fábrica. Su punto débil: agregar un nuevo tipo de producto obliga a modificar todas las fábricas.

Ejemplo visual

Ejemplo en código

from abc import ABC, abstractmethod

class FabricaUI(ABC):
    @abstractmethod
    def boton(self): ...
    @abstractmethod
    def checkbox(self): ...

class FabricaClaro(FabricaUI):
    def boton(self): return "Boton claro"
    def checkbox(self): return "Checkbox claro"

class FabricaOscuro(FabricaUI):
    def boton(self): return "Boton oscuro"
    def checkbox(self): return "Checkbox oscuro"

def pantalla(fabrica: FabricaUI):      # no conoce clases concretas
    return [fabrica.boton(), fabrica.checkbox()]

print(pantalla(FabricaOscuro()))

Builder

Introducción

Armas una hamburguesa paso a paso: pan, carne, queso, salsa. Eliges lo que quieres y solo al final te la entregan lista.

En programación

Patrón creacional para construir un objeto complejo por pasos. Evita constructores con muchos parámetros y permite validar que el objeto quede en un estado válido antes de entregarlo con build(). Cuesta más clases y código, así que no vale la pena para objetos simples.

Ejemplo visual

Ejemplo en código

class Carro:
    def __init__(self):
        self.marca = self.motor = self.color = None

class CarroBuilder:
    def __init__(self):
        self._c = Carro()
    def marca(self, m):
        self._c.marca = m; return self
    def motor(self, m):
        self._c.motor = m; return self
    def color(self, c):
        self._c.color = c; return self
    def build(self):
        if not self._c.marca:
            raise ValueError("falta la marca")
        return self._c

carro = CarroBuilder().marca("Kia").motor("1.6").color("rojo").build()

Cuadro comparativo

Abstract Factory frente a Builder. Regla práctica: si varían las familias de productos, Abstract Factory; si varía la configuración de un solo objeto complejo, Builder.

Abstract FactoryBuilder
ProblemaCrear familias de objetos relacionadosConstruir un objeto complejo paso a paso
ResultadoVarios productos distintosUn único producto final
EntregaInmediata en cada método crearX()Al final, con build()
EjemploInterfaz con tema claro u oscuroPetición HTTP, consulta SQL
VentajaGarantiza productos compatibles entre síEvita constructores con muchos parámetros
DesventajaUn nuevo producto obliga a tocar todas las fábricasMás clases para objetos simples
